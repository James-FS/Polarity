# 极性失控 / Polarity Unleashed — 剧情设计

> 版本：v0.1，2026-10-15<br>
> 状态：剧情提案与文案初稿，尚未接入游戏。<br>
> 依据：[玩法设计](./玩法设计.md) · [关卡设计](./关卡设计.md) · [技术架构](./技术架构.md)<br>
> 范围：在现有六关流程上补充背景、动机与情绪推进；本文不变更玩法规则、关卡布局或开发验收状态。

## 1. 剧情定位

采用“废弃设施中的维修机器人”方向。故事发生在一座即将封存的极性材料实验设施内，主角是一台没有战斗能力的小型维修机器人。

**一句话梗概：一台被列入回收名单的维修机器人，用仅有的极性改写权限，穿过仍在执行旧指令的设施，前往一座尚未关闭的维护站。**

整体气质克制、略孤独，结尾保留温暖。主要冲突来自设施的既定程序与主角求生愿望之间的错位，不设置必须击败的幕后反派。

剧情配合约 10—15 分钟的首次体验。玩家最先需要理解三件事：我是谁、为什么有危险、我要去哪里。世界历史和技术原理作为少量背景，不承担开场说明任务。

## 2. 背景与事件起因

### 2.1 设施的用途

这座设施研究可重写极性材料。部分机械外壳和运输装置采用同类材料，可以被维修工具写入正极或负极状态，并通过实际接触向尚未带极性的同类材料传递状态。

设施曾依靠这种特性搬运重物、调整设备间距和测试群体运动。如今研究工作已经结束，人员完成撤离，自动系统仍在按封存计划清点、回收和隔离设备。

设施没有在开场突然全面失控。广播、巡检与防卫程序仍各自运作，但已经没有人处理它们与现场情况之间的矛盾。

### 2.2 主角为什么醒来

主角在例行维护时刻自动唤醒。启动检查完成后，它收到最后一条调度任务：返回指定工位，等待回收。

它在本地检修记录中发现，“回收”包含拆解仍可工作的设备；记录里还保存着设施外一座维护站的位置。该站点没有被列入本次封存范围，最后一次状态报告仍为运行中。

主角开始尝试前往那里。这次偏离任务路线的行动，被巡检系统识别为待回收设备离位，随即触发追踪与拦截。

### 2.3 主角能做什么

主角持有一件极性维修工具，能够对指定材料进行有限次数的强制改写，却没有命令巡检机械或关闭防卫系统的权限。它必须利用接触、吸引、排斥、碰撞和设施火力解除威胁。

故事的变化由玩家的行动承载：起初只是保护自己，随后学会让多个局部变化相互影响，最后能够自行选择穿过危险的办法。

## 3. 角色与叙事声音

| 对象 | 设定与作用 | 表达方式 |
| --- | --- | --- |
| 维修机器人／玩家 | 小型、非战斗型维护单元；暂不固定姓名与编号，保留与现有美术衔接的空间 | 通过停顿、朝向与行动体现意图；首版无需对白或内心独白 |
| 自动调度广播 | 执行封存和回收流程，没有人格化恶意，也不会被主角说服 | 短句、平静、程序化；从例行提醒逐渐转为异常处置通知 |
| 巡检／回收机械 | 追踪离位设备的执行单元 | 使用已有追击敌人；赋极不改变其任务或敌对状态 |
| 离站技术员 | 只通过旧记录留下痕迹，曾维护这些设备 | 一两条实用便签，提供维护站线索与生活感；无需新角色立绘 |
| 外部维护站 | 主角明确的目的地，仍能接收维护单元 | 开场通过记录建立，结尾通过接收信息回应 |

广播只掌握设施监测信息，不负责评价玩家的具体解法。不要因为玩家没有按某条候选路线行动，就播放“操作错误”或“实验失败”。

## 4. 与现有玩法的对应

以下为世界观解释，不新增权限或交互入口。具体规则以玩法设计和实际配置为准。

| 现有玩法 | 叙事解释与边界 |
| --- | --- |
| 玩家没有普通攻击 | 维修机器人没有装备武器；极性工具原本服务于检修和搬运 |
| 仅敌人与箱子可主动赋极 | 它们使用可重写材料；正负极表示材料状态，不表示阵营或善恶 |
| 接触免费传播 | 同类材料接触时可传递状态；不是远程联网感染，也不是全群同步改色 |
| 已有极性不被接触覆盖 | 已写入状态保持，只有玩家的主动改写能切换；改色不追溯改变此前接收者 |
| 每关有限标记预算 | 工具在每个隔离区受强制写入限额约束；限额读取实际关卡预算，不在剧情里固定为三次 |
| 玩家不参与磁力与传播 | 主角采用不同于实验载体的非磁性机壳，不在可改写材料范围内 |
| 炮弹默认负极且不可标记、不传播 | 防卫弹体采用固定极性结构，与可重写材料载体的权限不同；不把炮弹描述为感染源 |
| 墙阻断磁力，箱子不阻断 | 隔离墙承担场区屏蔽，运输箱不具备相同结构；属于本作虚构设施设定 |
| 清除活动敌人后通关 | 当前区域的活动回收威胁解除，主角得以继续行程；不新增门锁、钥匙或必须摧毁炮台的目标 |
| 预算耗尽仍可移动 | 主动写入停止，既有材料状态与物理作用继续；不补充击杀返还或临时充能设定 |
| 慢速、暂停与重试 | 作为观察辅助和游戏流程保留，无需解释为主角控制时间或剧情中的复活 |

极性改写不会让敌人变成同伴，也不会造成自动伤害。中性表示无极性，不表示未激活或无威胁。故事不能把“吸住”“传播完成”写成必然清场。

## 5. 六关叙事推进

保留玩家第一至第六关的正式顺序。下表描述建议接入的故事内容，不表示场景装饰、广播或结尾已经实现。

| 关卡 | 故事位置与事件 | 情绪变化 | 可选环境线索 |
| --- | --- | --- | --- |
| 1 磁力试验室 | 主角完成唤醒检查，收到回收通知；面对首个回收单元，发现维修工具可以用于自保 | 从例行工作转为警觉 | 空置检修台、封存标签、本地维护站记录 |
| 2 接触扩散 | 回收程序扩大处置范围；主角借接触传播影响更多追击单元 | 从仓促应对转为发现可能 | 运输箱上的统一材料标识、停用的作业指示 |
| 3 借用火力 | 防卫设施仍执行原权限表；主角必须穿过火力覆盖区域 | 首次明显紧张，随后产生掌握局面的信心 | 无人值守的防卫控制台、固定极性警示 |
| 4 选择起点 | 主角抵达设备分流区，在不同局部关系之间自行选择干预方式 | 压力回落，主动判断增强 | 指向不同工位的地面标识，不作为必须遵循的路线箭头 |
| 5 改变通路 | 主角穿过封存隔离区，利用墙端与移动装置改变接触关系；旧记录再次确认维护站线索 | 孤独感加深，目标重新变得具体 | 隔离墙编号、一条技术员留下的实用便签 |
| 6 极性失控 | 最后一个回收区域汇集现有威胁；主角自行组合已学关系，解除活动拦截 | 紧张达到顶点，随后安静释放 | 封存区边界标识；通关后用结尾卡完成抵站叙述 |

第六关不新增规则、首领或“唯一正确方案”。借火、环境与混合路线都能通向同一结尾。也不要求用完标记、完成特定传播次数或展示某种队形。

## 6. 可接入文案初稿

### 6.1 开场

建议在首次开始前集中展示一次，可跳过。重试不重复播放。

> 设施人员已全部撤离。
>
> 今天，你的最后一项任务是返回回收工位。
>
> 检修记录显示，设施外还有一座运行中的维护站。
>
> 你带上极性工具，离开了指定路线。

开场只交代动机。正负极、传播和预算继续由玩法提示说明，避免把故事介绍与操作教学挤在同一段文字里。

### 6.2 六关广播

建议每关进入时最多使用一句。广播不得占用关键瞄准区域，也不因播放而强制等待。若没有安全的展示时机，可放在关卡介绍中阅读。

| 关卡 | 广播文案 |
| --- | --- |
| 1 磁力试验室 | “维护单元，请完成工具检查，随后返回回收工位。” |
| 2 接触扩散 | “检测到待回收设备离位。巡检单元开始接近。” |
| 3 借用火力 | “防卫系统仍在运行。当前设备未获通行授权。” |
| 4 选择起点 | “设备分流区。请按指定路线前往所属工位。” |
| 5 改变通路 | “隔离区已停止人工值守。维护请求暂不受理。” |
| 6 极性失控 | “封存前最终清点：仍有一台维护单元未归位。” |

广播体现系统始终将主角当作待回收设备。它不逐关获得愤怒、恐惧等人格，也不预告尚未发生的传播或击杀。

### 6.3 旧记录与便签

首版最多选用以下两条，保持可选阅读。不设置收集计数、交互谜题或依赖阅读的通关条件；可作为关间文字或装饰上的短句。

**开场本地记录：**

> 外部维护站：运行中。
> 接收范围：可自行抵达的维护设备。

**第五关技术员便签：**

> 外站的接收灯还亮着。需要检修的设备送去那里，别再往封存区里放。

便签只是日常工作的残留，不暗示技术员预知主角会觉醒，也不将全部事件解释为一场秘密安排。

### 6.4 结尾

第六关按现有规则清除全部活动敌人后，进入正常通关结算，再展示结尾。无需让玩家继续走到出口或启动新机关。

> 你离开封存区时，设施仍在重复最后一条回收通知。
>
> 维护站的接收灯亮了。
>
> “检测到维护单元。欢迎归站。”
>
> 你在空着的检修位前停下，提交了第一份由自己发起的维护申请。

结尾完成“从等待被处理，到主动请求维护”的变化。维护站的接收无需解释为获得人类身份或彻底觉醒；主角为自己作出的第一次选择已经足够。

### 6.5 对外故事简介

> 人员撤离后，实验设施开始回收所有设备。你是一台没有武器的维修机器人，唯一的工具只能进行几次极性改写。让状态沿接触传播，让吸引、排斥与敌方火力改变局面，穿过仍在执行旧指令的房间。设施外，还有一盏接收灯亮着。

## 7. 叙事呈现与制作范围

### 7.1 首版最小落地范围

1. 一份可跳过的开场文字，明确身份、危险与目的地。
2. 六句关卡广播，随正式关序显示，不干扰实时操作。
3. 一份末关结尾文字，在真实通关后展示。

以上均可先用文字完成，不要求配音、过场动画、人物立绘或新增可交互场景。广播可以作为文字提示，不以音频制作作为前提。

两条旧记录和少量封存装饰为可选补充。环境线索只帮助理解设施，不遮挡极性符号、脚下接触、炮台预警或危险边界。

### 7.2 文案与玩法提示的关系

- 玩法提示优先清楚说明操作、权限、剩余预算与失败原因；不要用“权限耗尽”等世界观词汇完全替代现有易懂术语。
- 故事广播与规则教学分开安排，同一时刻优先呈现玩家必须读取的信息。
- 不在战斗中弹出需要确认的长对话，不为完整播放剧情延迟真实胜利或失败。
- 重试不重复强制阅读，跳过剧情不影响预算、初始状态或可用解法。
- 文案只说明已经成立的事实；不得根据预设秒数宣称敌群已染色、炮弹已命中或主角已脱险。

### 7.3 后续实施边界

本文仅新增剧情设计，不启动编辑器，不修改代码、场景、Prefab、配置或现有实施记录中的完成状态。后续接入时复用现有流程与表现层，具体入口根据当时的界面版本确定。

接入验证只覆盖实际改动带来的文字、遮挡、跳过、重试和结算时序风险。仅增加文案与装饰时，不重跑全部物理解法；若新增流程改变模拟启停，再针对受影响行为验证。

## 8. 待定事项

- 主角是否需要名字或编号；现阶段使用“维护单元”即可。
- 开场与结尾最终采用纯文字、静态插画还是现有场景构图；先以文字完成内容评审。
- 六句广播中哪些保留在首版，哪些与关卡介绍合并，避免与实际教学争夺注意力。
- 环境美术稳定后，选择一至两处最合适的封存痕迹；不为剧情新增房间或改动必要通路。

这些事项不阻塞现有关卡制作。剧情内容先作为可评审初稿保存，实际接入与呈现效果另行记录。
