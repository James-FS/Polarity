# 极性失控 / Polarity Unleashed：美术资源规划

> 日期：2026-10-09
>
> 根据当前玩法设计与工程资源整理。数量为首版估算，尚未开始正式资源制作。

## 1. 整体方向

采用**带立体感的 2D 斜俯视实验室**。最终用于游戏的资源主要是角色精灵、道具精灵、场景拼接图、特效素材和 UI，不要求完整 3D 模型。

立体感由图片中的顶面、侧面、明暗、贴地阴影及前后遮挡共同形成。沿用当前正交相机和 XY 平面玩法，不要求精确等距菱形地图。

- 玩家暂定为小型机器人，敌人为追踪机械，箱子为金属装置。
- 地面、墙和装饰使用低饱和色，避免抢占玩法信息。
- 正极使用橙色和 `+`，负极使用蓝色和 `−`，无极性使用中性灰；颜色与符号同时表达状态。
- 玩家、敌人、箱子、固定炮台需要从轮廓上容易区分。
- 首版只制作一套实验室主题，通过不同布局组成关卡。

当前工程已有简单占位精灵、Enemy/Crate Prefab、分段墙体、贴地阴影和前后排序表现。它们用于验证结构与视角，正式美术仍待替换；当前进度以[实施步骤与验收记录](./实施步骤.md)为准。

## 2. 首版资源清单

| 类别 | 需要的内容 | 首版规模 | 优先级 |
| --- | --- | --- | --- |
| 玩家 | 小机器人；四方向待机、移动；受伤、死亡反馈 | 1 套角色 | 第一批 |
| 敌人 | 追踪机械；四方向待机、移动；受伤、死亡反馈；可显示极性 | 1 套角色，不扩展敌人种类 | 第一批 |
| 箱子 | 带顶面和侧面的金属箱；留出极性标识区域 | 1 种，外观变体可后补 | 第一批 |
| 场景模块 | 可拼接地板、墙顶、墙体立面、转角、低矮前景墙 | 1 套实验室模块 | 第一批 |
| 极性与选择提示 | 正负极符号、悬停轮廓、主动标记脉冲、接触传播闪光和来源提示 | 一套可复用表现 | 第一批 |
| 炮台 | 固定底座、独立转向炮管、蓄力和发射表现 | 1 套 | 第二批 |
| 炮弹 | 醒目的负极炮弹；可选短拖尾；命中表现 | 1 套 | 第二批 |
| 尖刺 | 清楚可辨的固定危险区，可重复拼接 | 1 种模块 | 第二批 |
| 其他特效 | 吸引/排斥提示、高速撞击火花、受伤闪白、死亡碎片、炮口闪光 | 连同标记和传播共约 6—8 类，可共用素材 | 第二批 |
| UI | 生命、敌人数、标记次数、操作提示、按钮、暂停/失败/通关面板 | 1 套简洁界面 | 第二批 |

## 3. 哪些适合生成，哪些在引擎里制作

整体是 2D 方案，但不需要把所有视觉内容都交给 AI 生成。

| 内容 | 建议方式 | 需要注意的地方 |
| --- | --- | --- |
| 角色静态外观、道具 | AI 生成基础图，再裁切、修图、统一比例 | 统一视角、光照和材质；清除生成图中的多余背景 |
| 地板、墙体、装饰 | AI 生成基础素材，再整理成可拼接模块 | 检查接缝、边缘、重复纹理和墙体遮挡 |
| 角色动画 | 基于确定的角色设计制作连续帧，必要时人工修帧 | 独立生成的图片不能直接当作连贯动画；轮廓、细节和脚下位置要稳定 |
| 极性变色、发光、受伤闪白 | 引擎中的颜色、材质或着色器表现 | 局部表达极性，避免把主体、阴影和所有细节一起染色 |
| 磁力连线、方向提示、标记脉冲 | 引擎绘制、缩放和透明度动画 | 根据实际对象关系显示，优先显示选中对象的相关关系 |
| 火花、碎片、炮口闪光 | 少量 2D 特效纹理配粒子或序列帧 | 素材可以共用，按事件调整颜色、大小和节奏 |
| 地面阴影 | 简单半透明精灵，在引擎中缩放和定位 | 与主体分离，始终贴地，不参与点击选择 |
| UI、正负极符号 | 矢量图、简单绘制和界面组件 | 保持清晰；文字使用字体组件，不烘焙进生成图片 |

角色和箱子的无极性、正极、负极状态优先共用主体图，通过局部变色、发光和符号切换表达，不必绘制三套完整外观。

## 4. 动画与反馈的最低要求

### 角色动画

- 玩家和敌人先做四方向简化待机、移动。
- 移动每方向可先采用 2—4 帧；待机采用单帧配轻微浮动或摆动。
- 左右方向在造型允许时镜像复用；非对称细节需要检查。
- 受伤优先用闪白和短暂抖动，死亡优先用火花和碎片，减少专用动画量。
- 箱子保持固定斜俯视外观，滑动由玩法驱动，不要求方向动画。
- 炮台底座与炮管分开制作，先验证炮管转向是否协调；需要时再补方向帧。

### 玩法反馈

| 事件或状态 | 视觉要求 |
| --- | --- |
| 鼠标悬停敌人或箱子 | 显示清晰轮廓，明确将要标记的对象 |
| 主动标记或改色 | 目标出现脉冲，极性符号立即变化，HUD 同步减少次数 |
| 接触传播 | 接收者闪光，显示实际来源；效果与主动标记区分，避免误以为传播也扣次数 |
| 吸引与排斥 | 用细连线、流动方向或箭头提示趋势，避免满屏关系线 |
| 高速撞击 | 火花和短暂冲击反馈；普通贴靠不使用同等强度效果 |
| 炮台蓄力 | 清楚显示预警方向和发射节奏 |
| 玩家受伤 | 闪烁或闪白，并让无敌状态容易辨认 |
| 标记预算用完 | HUD 明确提示仍可移动和重试，不显示为直接失败 |

仅敌人和箱子显示可标记轮廓。炮弹虽然默认负极，但不可主动标记，也不传播极性；其外观应避免与可标记目标混淆。

## 5. 素材统一与交付约定

正式批量制作前，先选定一组角色、箱子和墙体样图，在游戏中确认以下约定。

- **视角一致：** 所有主体使用同一套斜俯视角度和透视程度。
- **光照一致：** 顶面、侧面的明暗关系及主要光照方向统一。
- **比例一致：** 角色、箱子、炮台与墙在实际单屏画面中比例协调。
- **脚下锚点一致：** 动画各帧使用相同画布和接地参考点，防止播放时漂移。
- **主体与阴影分离：** 角色、道具图片不烘焙大面积地面阴影，阴影由独立精灵表现。
- **透明边缘干净：** 主体优先交付透明背景 PNG，检查白边、黑边和残留背景。
- **状态标识可读：** 为极性符号预留空间，在游戏实际显示尺寸下仍能识别。
- **模块可拼接：** 地板和墙体检查重复拼接；前景墙保持低矮，必要时支持淡化。

具体像素尺寸和导入比例在第一组素材入场后确定，整套采用统一标准。高分辨率原图不能代替实际游戏尺寸下的可读性检查。

角色身体和箱子立面可以向脚下位置上方延伸。美术图的高度不代表碰撞高度，实际碰撞仍使用脚下占地；图片重叠不等于实体接触。

## 6. 制作顺序

1. **统一样式：** 确定玩家、敌人、箱子、地板和墙体的基础外观，验证视角、比例、光照与阴影。
2. **完成一个房间：** 替换基础白盒，补齐极性标识、悬停轮廓、主动标记和传播效果，检查玩法信息是否清楚。
3. **补齐首版内容：** 制作炮台、炮弹、尖刺、必要动画、撞击与受伤反馈、基础 UI。
4. **复用到其他关卡：** 使用同一套模块调整布局，检查群体交互时的遮挡和特效密度。
5. **有余力再包装：** 补装饰、Logo、封面和更细致的演出。

首版建议把美术预算集中在角色辨识、极性状态和传播反馈上。暂不扩展多个场景主题、多种敌人、复杂死亡动画或大量装饰。

## 7. 首批验收

- 一个完整房间中的角色、箱子、墙体具有一致的体积感。
- 前后遮挡正常，贴地阴影与动画脚下位置稳定。
- 玩家能一眼区分玩家、敌人、箱子、炮台和危险区。
- 无极性、正极、负极同时通过颜色和符号区分。
- 主动标记与免费传播的反馈容易区分。
- 前景墙和装饰不会长期遮住目标或干扰选中。
- 多对象交互时，特效不会淹没角色、极性符号和炮弹。

本规划只定义资源范围与制作方式，不代表对应玩法或美术已经实现。
