**目标：** 建立可复用的测试房间，物理保持 XY 平面，外观呈现立体感。

**已完成工作：**

- 建立 Polarity 资源目录、Game.scene、16 × 9 白盒房间与 Enemy/Crate Prefab；配置零重力、冻结旋转、墙体碰撞、Physics Layer 与碰撞矩阵。
- 使用正交相机正对 XY；实体根作为脚下锚点，VisualRoot/SortingGroup 管理身体、顶面与侧面，GroundShadow 独立贴地。
- 建立 Ground → GroundShadow → World → Effects 渲染层；YSortView 按脚下 Y 排序，墙体占地与立面分开，前景墙降低高度。
- 保存场景和 Prefab，保留原 SampleScene。步骤 1 验收时使用自动 FixedUpdate 物理；现已由步骤 2 的 World 在运行时接管模拟。

**验收摘要：**

- [x] 房间与主体可见，敌人身体、箱子顶面/侧面及阴影可辨认，Console 无编译错误。
- [x] 静置 2 秒无漂移；敌人/箱子以 6 单位/秒撞向四面墙，8/8 项接触与边界检查通过。

## 步骤 2：极性状态与唯一模拟入口（已完成）

**目标：** 在步骤 1 的资产上建立核心运行状态，统一接管物理。

**要做的事：**

- 新增 Polarity、LevelPhase、LevelState、PolarityBody、SimulationWorld、最小 PolarityView。定义 Neutral/Positive/Negative 与 Ready/Running/Paused/Won/Lost。
- PolarityBody 保存刚体、初始/当前极性、权限与稳定 BodyId；Enemy/Crate 可标记、传播及接收，玩家不参与极性。按明确初始列表分配 ID，依赖和注册完成后才进入 Running。
- World 切换为 Script 模拟，仅在 Running 的 FixedUpdate 调用一次 Simulate；失败时记录错误并停止本步提交，退出时恢复接管前的模式。其他组件不自行推进物理或重复施力。
- View 初始化读取并订阅状态，橙正/蓝负/灰 Neutral，只更新主体与符号；阴影独立，退出时取消订阅。

**验收：**

- [x] 每固定步只有一次物理推进，动态对象碰撞正常；非 Running 不推进。
- [x] 初始极性与显示一致，稳定 ID 无重复，不依赖 Start 顺序或 GetInstanceID。
- [x] 停止运行恢复原物理模式，没有重复模拟或失效订阅。

**验收摘要：** 2026-10-09 通过 35 项运行检查、5 项防护检查及重开 Play 验证；两实体对四面墙的 8 项碰撞测试通过。物理参数保留，保存重载后无 Missing Script，最终 Console 无错误或警告。详细证据见[实施记录](./实施记录.md)与[步骤 2 验收数据](./verification/步骤2-验收.json)。

## 步骤 3：吸引与排斥（已完成）

**目标：** 步骤 2 通过后，确认磁力方向、尺度与稳定性。

**要做的事：** 建立 GameplayConfig，配置强度、半径、标记距离、加速度与安全速度上限。World 遍历对象对 i < j，按技术架构的平滑力函数施加等大反向力；Neutral、超范围或隔墙跳过，箱子不阻断。AddForce 不重复乘 deltaTime，中心重合用稳定方向，Gizmos 显示范围与力。先用两物体的初始极性测试，再增加数量。

**验收：**

- [x] 同极排斥、异极吸引、Neutral 无力；每对只算一次，相同力下轻物体加速更明显。
- [x] 超范围/隔墙无力，异极贴靠不剧烈抖动，近重合无 NaN 或爆速。
- [x] 安全限速仍允许正常偏转与弹射。

**验收摘要：** 2026-10-09 通过 38 项磁力/模拟检查、8 项墙体碰撞回归及保存重载、重开 Play 验证。新增 GameplayConfig，World 在唯一物理入口内累计成对力并执行安全限制，提供 Scene View Gizmos。Game 场景沿用原位置，实例初始极性设为 Enemy 正极、Crate 负极以直接演示吸引；Prefab 默认仍为 Neutral。详细证据见[实施记录](./实施记录.md)与[步骤 3 验收数据](./verification/步骤3-验收.json)。

## 步骤 4：玩家移动与有限标记（已完成）

**目标：** 步骤 3 通过后，让玩家用三次标记干预运动。

**要做的事：** 新增 PlayerController、MarkingController、MarkRequest。玩家使用脚下 Dynamic 刚体、VisualRoot 与独立阴影；Update 缓存 WASD，World 驱动刚体。确认输入配置与 API 匹配，先不新增输入框架。左键正极、右键负极；按可见主体与实际排序选目标，忽略阴影/装饰/炮弹，提交根 ID。World 按请求顺序校验阶段、有效性、权限、脚下距离、墙体遮挡、同色与预算；赋极/改色扣 1 次，无效不扣。预算放在 LevelState，先用调试文字显示，无清除极性、自动恢复或返还。

**验收：**

- [x] WASD 可控，玩家不受磁力；点击身体上部能选中，重叠候选符合画面，阴影不误选。
- [x] 三次有效操作后不能改色但仍可移动；同色、空白、遮挡、过远等不扣次数。
- [x] 改色消耗 1 次并改变运动，快速连点不重复消费、不产生负预算。

**验收摘要：** 2026-10-09 通过 51 项移动/选中/预算检查、14 项碰撞与生命周期回归、11 项真实固定步连续运行检查；三项验收全部通过。玩家复用机器人结构，不挂 PolarityBody；标记按主体屏幕范围与 SortingGroup 选择，再由 World 以脚下位置校验。有序消费 40 个连点请求无重复扣次或负预算，改色即时反转磁力，预算耗尽仍能移动。保存重载和重开 Play 后初值正确，最终 Console 错误 0、警告 0。详细证据见[实施记录](./实施记录.md)、[步骤 4 验收数据](./verification/步骤4-验收.json)与[最终画面](./verification/步骤4-最终画面.png)。

**已知限制：** 主体使用屏幕包围矩形命中，透明边角可能被选中；候选轮廓和英文文字是临时调试表现。验收通过游戏输入采样/请求 API 驱动真实物理，未注入物理键鼠或验证独立构建。正式 R 重试在步骤 8 完成，当前通过重开 Play Mode 恢复测试状态。

## 步骤 5：受磁力影响的追击敌人（已完成）

**目标：** 步骤 4 通过后，让追击与磁力共同影响接触机会。

**要做的事：** 新增 EnemyMotor，由 World 显式调用有限追击驱动力；不直接覆盖最终速度。区分追击上限与全局安全限速。先验证开放房间，再加入简单通道与轻量避障；扩展为六个无极性敌人、一个箱子，初始不重叠，追击时有接触机会。

**验收：**

- [x] 无极性敌人持续追逐玩家，标记后路线能被磁力偏转。
- [x] 玩家走位会改变接触机会，敌人不瞬移或穿箱，没有独立 FixedUpdate 重复施力。

**验收摘要：** 2026-10-10 通过 21 项开放房间检查、14 项六敌人走廊检查及 9 项真实固定步连续运行检查，共 44 项。EnemyMotor 仅由 World 调用有限驱动力，追击速度 3.2、驱动加速度上限 6，全局安全速度仍为 12。Game 复用已有 Prefab 扩展为六个 Neutral 敌人、一个负极箱子和简单通道；两种玩家走位产生不同接触时机与对象组合，标记后磁力可偏转追击。保存重载后初值正确，最终退出 Play，Console 错误 0、警告 0。详细证据见[实施记录](./实施记录.md)、[步骤 5 验收数据](./verification/步骤5-验收.json)与[最终画面](./verification/步骤5-最终画面.png)。

**已知限制：** 避障只处理局部墙体/箱子，没有全局寻路；凹形或 U 形迷宫可能卡住。本次使用游戏采样/请求 API 驱动真实物理，未注入物理键鼠或进行独立构建。接触传播留在步骤 6。

## 步骤 6：接触采集与快照传播

**目标：** 步骤 5 通过后，让传播按统一规则稳定结算。

**要做的事：** 新增 ContactRecorder、接触数据、PropagationSystem 与结果数据。主动标记后、物理前建立快照；回调只复制数值，模拟后用 GetContacts 补充持续接触，按稳定 ID 归一化/去重，检查缓冲区扩容。敌人/箱子按权限传播：有极性传给 Neutral，所有候选读取同一快照，最后统一提交，新接收者下一轮才可传播。冲突按去重后的接触冲量，接近相同时按稳定来源 ID；传播免费、源头保留极性、已有极性不覆盖。调试显示步号、接触对及实际来源/目标，与主动标记区分反馈。

**验收：**

- [ ] A 正极、B/C Neutral 且 A—B—C 接触：第一轮只改变 B，下一轮仍接触才改变 C。
- [ ] 已贴靠对象后来被标记仍可传播；敌人↔敌人、敌人↔箱子、箱子↔箱子规则一致。
- [ ] 已有极性不覆盖，传播不扣预算，每个接收者每轮最多一个结果，遍历顺序不改变一轮传播范围。

一步一跳不保证视觉上很慢；传播过快或立即中断时，先调间距、排斥和追击。

## 步骤 7：核心反馈验收（扩展前的关口）

**目标：** 步骤 1—6 通过后，验证“传播改变运动，运动改变接触与传播”能形成玩家可利用的局面。

**要做的事：** 固定六敌人、一个箱子、通道布局与预算，每次只改一个变量：首个标记对象、时机、玩家站位，或给箱子负极后保留一次改正极的干预。将实验的起点/时机、传播变化、运动变化、候选用途记入实施记录。

**验收：**

- [ ] 同一布局产生至少两种可解释、可复现的整体局面，少量干预能改变传播路径或群体运动。
- [ ] 能指出拆散追击队伍、引导位置或制造撞击等候选用途，结果不总是全体染色后同样四散。

**未通过先调试，再扩内容。** 检查接触有效性、追击是否覆盖受力、力与质量比例、间距和墙体布局。此时只证明反馈与候选用途；实际避险、击杀与通关价值在步骤 8—9 继续验证。

## 步骤 8：伤害、胜负与快速重试

**目标：** 步骤 7 通过后，形成能胜利、失败与重试的战斗原型。

**要做的事：** 新增 Health、DamageSystem、LevelController 与结果数据。按碰撞时法向相对速度判伤，配置阈值与受伤间隔，去除双边重复；尖刺 Trigger 进入伤害记录，独立于传播。先标记死亡，再排除无效双方并计算传播，最后统一注销/销毁。清空敌人且玩家存活则胜，玩家死亡优先判负，预算为零不判负。注册完成才检查胜负，结束后停止危险模拟。R 重载 Game 恢复位置、极性、生命、预算及正常时间倍率，清理请求、接触、事件、冷却和 ID。

**验收：**

- [ ] 高速箱子撞敌人或敌人撞墙可伤害，低速贴靠不磨血，同次碰撞不重复扣血，死亡对象不传播。
- [ ] 已验证的群体变化在战斗中确实带来避险或击杀机会。
- [ ] R 恢复完整初始状态，无旧请求；胜负后可重试，胜利后无残留危险攻击。

## 步骤 9：炮台与默认负极炮弹

**目标：** 步骤 8 通过后，让敌方火力成为可利用的工具。

**要做的事：** 新增 Turret、Projectile 与 Prefab。炮台固定、不可摧毁，不参与磁力、不计清除目标；World 控制瞄准、预警、锁定及发射。炮弹为负极 Dynamic，参与磁力，CanMark/CanSpread/CanReceive 全关；快照前初始化/注册，生成位置避开炮台。炮弹大而少、可明显偏转，无追踪或范围爆炸；伤害统一消费一次，撞箱子/墙/固定障碍销毁，查询与 UI 排除炮弹。

**验收：**

- [ ] 预警清楚，玩家可用正极敌人引导炮弹造成伤害，发射后只受物理与磁力影响。
- [ ] 炮弹不可标记、不传播、不重复命中；箱子挡弹，最高设计速度下无频繁穿墙。
- [ ] 炮弹注册、消费与注销无列表修改异常。

## 步骤 10：HUD、慢速与暂停

**目标：** 步骤 9 通过后，补齐操作与状态反馈。

**要做的事：** 新增 HUDView、胜负/暂停界面与表现事件。显示生命、敌人数、预算、操作提示；初始化读状态，再订阅实际结果并成对取消订阅，传播事件携带实际来源/目标。正负极兼用颜色与符号。空格慢速先用 0.3，固定步长保持，不再给力或 Simulate 步长重复乘倍率；Esc 暂停，Update 仍处理恢复/R。炮台与冷却用模拟时间，菜单可用非缩放时间；暂停/胜负/重试清空世界请求，UI 点击不标记，次数用完提示仍可移动/重试。

**验收：**

- [ ] HUD 初始正确，主动标记与传播可区分，UI 点击不扣预算。
- [ ] 慢速与暂停组合后恢复倍率正确，R 回到正常速度，暂停前请求不在恢复后执行。
- [ ] 多次重试无重复订阅、音效或失效引用。

## 步骤 11：教学与综合关卡

**目标：** 步骤 10 通过后，让核心玩法形成完整关卡流程。

**要做的事：** 新增 LevelDefinition、关卡 Prefab、顺序与切关逻辑；固定初始对象顺序、极性、炮台节奏和预算，完整初始化后开始。按玩法设计先打磨前三关教学，再扩展综合关，目标六关，时间不足优先四关。稳定规则提取为 MagnetismSystem/PropagationSystem/DamageSystem，参数统一到配置或 Prefab，运行状态不写回配置、不跨关残留。

**验收：**

- [ ] 教学能说明标记/改色、接触传播与炮弹权限；每关至少一种预算内稳定解法，有合理操作余量。
- [ ] 综合关尽量支持两种解法，不依赖像素级时机；不同起点或时机能改变打法。
- [ ] 预算鼓励利用传播，下一关与重试恢复正确配置，无前关预算、ID 或接触残留。

## 步骤 12：反馈打磨与外部试玩

**目标：** 步骤 11 通过后，验证玩家能理解原因并发现用途。

**要做的事：** 替换正式机器人、箱子、地面和墙体素材，统一接地锚点，保持极性醒目；补充四方向简化动画、独立炮管转向、标记/传播/撞击/受伤/预警，只更新视觉子对象。关系连线优先选中对象。邀请不了解设计的人试玩，不提前解释解法，记录理解障碍与自创用途；先修误解、卡死与预算问题，再做装饰，正式界面移除调试信息。

**验收：**
