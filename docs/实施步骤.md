按用户节省额度的要求，后续执行以[项目约束](../AGENTS.md)为准。下面的验收项目是需要证明的行为，不是一项一轮的测试数量；一次真实运行可同时覆盖多个项目，已有同版本证据直接复用。

**目标：** 六关各至少有一条完整路线后，验证真实玩家按 1—6 顺序学习和决策；后半程多解目标仍有缺口时明确保留待迭代状态。

**要做的事：**

- 在 Game 中按玩家顺序完整运行六关一次，同时核对初值、HUD、实际下一关与跨关残留。慢速、暂停和失败重试选代表关卡检查，已覆盖且代码未改的共同流程引用原证据，不在六关各重跑一遍。
- 检查学习衔接：第一关受力 → 第二关接触与不覆盖 → 第三关炮弹权限 → 第四关局部改色 → 第五关墙体和移动来源 → 第六关自主组合。制作时先搭第四/五关不能导致玩家提前遇到未解释的规则。
- 依据关卡设计第 3.3、10 节比较完整路线、时机/站位余量、无标记对照与多解差异。第五关风险未解决或第四/六关策略仍重复时，单独继续迭代，不用“六关均可通关”代替策略验收。
- 邀请至少 3 名未读设计的玩家按顺序试玩，优先复用现有界面和可读白盒，不提前告知候选解法。使用正常生命/预算，记录首次标记、受伤、重试、慢速、理解障碍、等待和自创用途。
- 优先使用可运行的开发构建进行试玩；若暂时只在编辑器测试，明确记录环境，不能据此勾选独立构建验收。构建时照常记录真实输入，不仅使用开发者 API 重放。
- 逐关询问关键因果与下一次想改变什么：传播为何中断、炮弹为何打箱、改敌与改箱有何差别、墙后为何没有磁力。根据观察优先修误解、卡住、预算与残敌问题，再补提示或装饰。
- 每次优先修改一个空间变量，并重验受影响的候选路线。统计首次整套体验与熟练用时，约 10—15 分钟只作首次体验参考，不强制每关达到 30—90 秒。

**验收：**

- [ ] 新布局六关可按正式顺序从头完成，下一关、慢速、暂停、失败与重试没有旧状态或事件残留。
- [ ] 第四至第六关各两条具有实质区别的完整路线已验证；未达标项明确列为待迭代，不提前勾选。
- [ ] 至少 3 名未读方案玩家的记录真实完整；玩家能解释基本权限、免费传播和主要变化，并能提出下一次调整。
- [ ] 初轮理解障碍、无意义等待、持续卡住与预算问题已有修复及受影响路线复验，学习曲线没有未教学就致命测试的突变。
- [ ] 至少第四或第六关的同布局/同预算对照显示不同且可利用的整体局面；自创用途与偶发混乱区分记录。

**未通过时：** 回到对应关卡步骤修改白盒，不把美术替换当修复。不因一次试玩未发现某候选就认定不存在，也不因开发者会操作就认定新玩家能够理解。

## 步骤 20：因果反馈、必要教学与正式表现（待实施）

**目标：** 白盒关系基本稳定、首轮试玩问题已定位后，完成对玩法有实际帮助的表现；保持脚下物理与共同规则。

**要做的事：**

- 根据试玩优先补清楚的候选轮廓、赋极脉冲与扣次、免费传播来源/接收闪光、磁力关系、有效撞击、尖刺伤害、玩家受伤和炮台预警。普通贴靠不用高速撞击反馈，关系线优先当前关注对象，不铺满屏幕。
- 保持正负颜色与符号双重表达；预算零仍提示可移动/重试。第三关明确炮弹权限，第四关明确改色只作用于一个对象，第五关明确墙体遮挡；不把候选操作顺序写成唯一答案。
- 第一关静止准备与真实状态提示已按用户追加要求补充，见新手引导验收；本步骤按试玩观察继续调整。准备期间不提前赋极，进入实时阶段后权限不变；动态提示不按固定秒数伪称传播/吸引成功，提前清场照常结算。
- 替换机器人、箱子、地面和墙体素材，统一底面锚点、阴影、Y 排序与前景立面。先改一个代表房间检查尺寸与选中，再批量应用；四方向简化动作和炮管转向仅修改视觉子对象，不转动物理根或改变占地。
- 补必要音效与简短伤害反馈，暂停/胜负/重试不能留下重复订阅、重复声音或旧特效。效果不延迟接触结算、不推动对象、不改变力与伤害来配合演出。
- 检查素材重叠、立面和效果是否掩盖脚下接触或危险边界。打磨后重验受影响路线与教学，再做少量新玩家复测，不先制作与理解无关的装饰或额外系统。

**验收：**

- [ ] 正常速度能辨认标记、传播、磁力、命中和伤害来源，慢速只辅助观察；各关预算和对象权限未被表现改写。
- [ ] 主提示简短且不强制指定解法；若增加准备/动态提示，错误操作、提前清场、暂停、重试与耗尽预算分支均不阻塞。
- [ ] 身体、箱子顶侧面、阴影与前后遮挡清楚，前景墙/HUD 不长期挡住关键对象，图片重叠不冒充真实接触。
- [ ] 新素材与视听应用后，受影响的预算内路线、选中、伤害和流程已复验，未新增碰撞占地或模拟入口。
- [ ] 复测中主要误解有改善；若仍有卡死或等待，已回到白盒调整，不用更多特效掩盖问题。

**范围控制：** 优先能帮助读懂因果的反馈。准备状态、动态提示和额外装饰不是完成物理解法的条件；时间紧时先减少非必要表现工作，保留可读与可玩的核心。

## 步骤 21：最终规则回归、目标平台构建与交付（待实施）

**目标：** 新关卡与表现稳定后，完成真实目标平台上的整套运行验证和完整交付包。

**要做的事：**

- 复用已有规则/流程夹具与新关运行证据，重点回归本轮改动相关关系：一步一跳、已有极性不覆盖、主动改色计次、死亡不传播、墙体遮挡、低速无撞击伤害、炮弹权限/消费与胜负冻结。只有存在未覆盖的实际风险时补针对性检查，不强制为本轮重新开发测试框架。
- 核对目标平台、jam 截止与包格式、Game 启动场景、引擎和依赖。运行状态与 GM 修改不保存进资产，正式发布构建应隐藏调试面板且不能残留无敌/无限标记。
- 执行真实构建并从干净启动独立运行。验证实体键鼠、选中、中文字体与符号、音频、相机/HUD、所有关卡、下一关、慢速、暂停、失败及重试；API 重放不能替代玩家输入与独立运行。
- 至少验证已用 1280×720 与一个实际支持的目标窗口/比例，检查关键交互可见、UI 不遮挡和点击映射正确。测试最高设计速度下的边界/薄障碍和稳定帧运行，不宣称未测试的任意比例或跨设备完全确定性。
- 完成独立构建中至少一次从第一关至末关的正常预算流程；复核后半程不同策略在构建中仍可用，对平台差异或性能导致的问题修改后复验。
- 整理完整可运行文件、操作与重试说明、已知限制、截图和版本信息；从实际交付包再次解压/启动检查，不只验证编辑器输出目录。截图和介绍仅描述已验证内容，多解未通过或方案降级需如实记录。

**验收：**

- [ ] 相关规则/流程回归通过，无未处理错误或 Missing Script；新布局证据与旧记录分开。
- [ ] 独立构建可正常输入并从启动完成全部关卡，暂停/慢速/切关/重试正确，不依赖编辑器或 GM 手工状态。
- [ ] 中文字体、符号、音频、支持分辨率、点击与最高设计速度碰撞已在目标环境验证。
- [ ] 正式构建隐藏 GM 且无作弊状态，打磨后的完整路线仍在预算内，未验证的策略不被写成已完成。
- [ ] 实际交付包能再次启动，所需文件与说明完整，目标平台和 jam 提交要求已经核对。

**完成标准：** 实际构建与验证通过后再将步骤勾选、证据和剩余限制追加到实施记录，并同步真实进度。本文只是后续工作计划，不表示已执行新关制作、试玩、构建或发布。
